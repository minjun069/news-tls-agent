# 화면설계서 — news-tls-agent

관련 PRD: [`REQUIREMENTS.md`](../REQUIREMENTS.md) · API: [`API.md`](../contracts/http-api.md)

> **화면 표기 규칙은 이 문서가 단일 원천이다.** 기능 요구사항의 정책은 판정을, 이 문서는 표기를 담는다.

---

## 1. Information Architecture

```
/                        이슈 목록
└─ /issues/:id           이슈 상세
   ├─ 타임라인 (기본)
   │  └─ 대표 기사 (선택 시 즉시 표시)
   │     └─ 근거 기사 목록 → 기사 원문
   ├─ 대화 (패널)
   └─ 지식 그래프 (패널)
```

화면 2개, 패널 3개. 라우팅 계층을 얕게 유지한다.

---

## 2. 화면 목록

| 화면 | 목적 | 관련 요구사항 |
|---|---|---|
| 이슈 목록 | 생성된 이슈를 확인하고 새 토픽을 입력한다 | ISS-001, ISS-002, ISS-004, ISS-006 |
| 이슈 상세 | 타임라인을 읽고 근거를 확인하며 질문하고 내보낸다 | ISS-005, ART-001~003, CHAT-001~006, EXP-001, EXP-002, GRPH-001 |

### 2.1 이슈 목록

- 토픽 입력창 + 생성 버튼
- 이슈 카드 목록 (제목, 토픽, 생성 시각, 이벤트 수)
- 생성 중에는 진행 단계와 라운드 표시
- 되묻기가 오면 질문과 답변 입력창 표시

### 2.2 이슈 상세

- 헤더: 표시 제목, 토픽, 생성 시각, 내보내기 메뉴
- 요약 (마크다운 렌더링)
- 타임라인: 이벤트를 날짜 오름차순으로 표시
- 이벤트 선택 시 **대표 기사가 즉시 펼쳐짐**
- 대표 기사 아래에 나머지 근거 기사 목록 (접힌 상태)
- 대화 패널
- 지식 그래프 패널

> 심층 분석·핵심 용어 영역은 없다 ([PRD 비목표](../REQUIREMENTS.md#35-비목표)).

## 3. 화면 플로우

### 3.1 타임라인 생성 (시나리오 1)

```
이슈 목록
   │ 토픽 입력 → 생성
   ▼
진행 표시  ── intent → hypothetical → search(R1) → select(R1) → …
   │
   ├─ clarify 이벤트 → 되묻기 표시 → 답변 입력 → 재요청
   ├─ done            → 이슈 상세로 이동
   ├─ cached          → 이슈 상세로 즉시 이동
   └─ error           → 목록에 머무르며 안내 표시
```

### 3.2 근거 확인 (시나리오 1 후반)

```
이슈 상세 → 이벤트 선택 → 대표 기사 즉시 표시
                              ├─ 본문 확인
                              ├─ 근거 기사 목록 펼치기 → 다른 기사 선택
                              └─ 원문 URL (새 탭)
```

### 3.3 대화 (시나리오 2)

```
이슈 상세 → 대화 패널 → 질문 입력
   │
   ├─ tool 이벤트  → "기사 검색 중" 표시
   ├─ token 이벤트 → source에 따라 표기를 달리해 점진 표시
   └─ done         → 참조 기사 ID를 근거 링크로 표시
```

### 3.4 내보내기 (시나리오 3)

```
경로 A  이슈 상세 → 내보내기 메뉴 → PDF / Notion 선택
경로 B  대화 패널 → "PDF로 저장해줘" → 에이전트가 도구 호출 → 파일 카드 표시
```

두 경로의 결과 표시는 동일하다.

## 4. 화면 표시 기준

상태값 정의는 [`DATA.md`](../data/source-and-ingestion.md), 판정 규칙은 각 기능 요구사항을 원천으로 한다. 여기서는 **표기 방식**만 정한다.

### 4.1 생성 실패

| 상황 | 금지 표현 | 권장 표현 | 재시도 버튼 |
|---|---|---|---|
| `no_articles` | `생성 실패` | `관련 기사를 찾지 못했습니다. 다른 토픽으로 시도해 보세요.` | 없음 |
| `generation_failed` | `기사가 없습니다` | `생성에 실패했습니다. 다시 시도할 수 있습니다.` | 있음 |
| `rate_limited` | `오류가 발생했습니다` | `요청이 많아 잠시 후 다시 시도해 주세요.` | 있음 |

**앞의 둘을 같은 문구로 묶지 않는다.** 사용자가 취해야 할 다음 행동이 다르다.

### 4.2 생성 진행 — ISS-002

| 상황 | 금지 표현 | 권장 표현 |
|---|---|---|
| 라운드가 진행 중 | `처리 중…` 만 표시 | `2번째 검색 중 · 기사 21건 확보` |
| 단계 전환 | 무표시 | 현재 단계명을 갱신 |
| 오래 걸리는 단계 | 정지한 것처럼 보임 | 진행 중 표시를 유지 |

라운드 번호를 보여주는 이유는 **루프가 돌고 있다는 사실 자체가 정보**이기 때문이다. 단순 로딩 표시는 멈춘 것처럼 보인다.

### 4.3 되묻기 — ISS-006

| 상황 | 금지 표현 | 권장 표현 |
|---|---|---|
| 의도가 모호할 때 | 임의로 해석해 진행 | 질문을 보여주고 답변 입력창 제공 |
| 되묻기 표시 | 오류처럼 보이는 스타일 | 대화 형태의 안내 |
| 상한 도달 후 | 계속 되묻기 | 해석된 의도를 알리고 진행 |

되묻기를 오류처럼 보이게 하면 사용자가 실패로 오해한다.

### 4.4 근거 기사 — ART-001, ART-003

| 상황 | 금지 표현 | 권장 표현 |
|---|---|---|
| 이벤트 선택 | 목록만 표시하고 한 번 더 클릭 요구 | **대표 기사를 즉시 펼침** |
| 근거 기사가 2건 이상 | 전부 펼쳐 화면을 채움 | 대표 기사만 펼치고 나머지는 `근거 기사 N건 더 보기` |
| 본문이 잘린 경우 | 잘린 표시 없이 본문만 | 본문 끝에 `일부만 표시됨` + 원문 링크 |
| 원문 URL이 없는 경우 | 비활성 링크 | 링크 자리를 비우고 안내 없음 |

> 근거 기사가 0건인 이벤트는 화면에 나타나지 않는다. 저장 단계에서 제외되기 때문이다.

### 4.5 대화 출처 표기 — CHAT-004

`token` 이벤트의 `source` 값에 따라 표기를 달리한다.

| source | 금지 표현 | 권장 표현 |
|---|---|---|
| `article` | 근거 없이 본문만 | 문단 끝에 근거 기사 ID를 링크로 표시 |
| `general` | 기사 근거와 같은 스타일 | 문단에 `기사에서 확인되지 않은 설명` 표식 |

**두 출처를 같은 스타일로 렌더링하지 않는다.** 시각적으로 구분되지 않으면 CHAT-004가 무의미해진다.

| 상황 | 금지 표현 | 권장 표현 |
|---|---|---|
| 확인 불가한 질문 | 모델이 추측한 답변 | `기사에서도 확인되지 않고 일반적으로도 단정하기 어렵습니다` |
| 도구 호출 중 | 무표시 | `기사 검색 중…` |
| 답변 생성 중 | 완성까지 빈 화면 | 수신한 토큰을 즉시 표시 |
| 데이터 접근 실패 | `답변할 수 없습니다` | `자료를 불러오지 못했습니다. 다시 시도해 주세요.` |

### 4.6 내보내기 — EXP-001, EXP-002

| 상황 | 금지 표현 | 권장 표현 |
|---|---|---|
| PDF 생성 완료 | 자동 다운로드만 | 파일 카드 + 다운로드 링크 |
| Notion 저장 완료 | 완료 문구만 | 생성된 페이지 URL을 링크로 제공 |
| Notion 미설정 | `실패했습니다` | `Notion 연결 설정이 필요합니다` + 설정 안내 |
| 대화에서 형식 미지정 | 임의 형식으로 실행 | 어떤 형식으로 저장할지 되묻기 |

### 4.7 지식 그래프 — GRPH-001

| 상황 | 금지 표현 | 권장 표현 |
|---|---|---|
| 추출이 필요한 기사가 있을 때 | 빈 화면 유지 | `관계를 분석하는 중 · 남은 기사 N건` |
| 그래프 표시 | 여러 기사를 한 화면에 겹쳐 표시 | **기사별로 그래프를 분리해 표시** |
| 각 그래프 | 출처 없이 노드만 | 그래프마다 출처 기사 제목·날짜를 함께 표시 |
| 노드 수가 상한을 넘을 때 | 전부 그려 판독 불가 | 표시 대상을 줄이고 축소했음을 알림 |
| 이벤트 1건 이하 | 빈 그래프 | 그래프 영역을 표시하지 않음 |

> 기사별로 분리하는 이유는 엔티티 표기를 정규화하지 않기 때문이다. 합치면 같은 인물이 여러 노드로 갈라져 오히려 잘못된 인상을 준다.

### 4.8 로딩과 지연

| 상황 | 표시 |
|---|---|
| 조회 지연 | 1초 이상이면 스켈레톤 |
| 응답 지연 | 5초 이상 첫 토큰이 없으면 `응답을 기다리는 중` |

### 4.9 마크다운 렌더링

- 요약은 마크다운으로 렌더링한다
- 코드펜스는 사용하지 않는다 (모델 출력 규칙)
- 표가 화면 폭을 넘으면 가로 스크롤 영역 안에서 처리한다
