# 이슈·기사 조회 요구사항

관련 공통 PRD: [`../REQUIREMENTS.md`](../REQUIREMENTS.md)

## 요구사항

| ID | 요구사항 | 우선순위 | 상태 |
|---|---|---|---|
| ISS-004 | 생성된 이슈 목록을 조회할 수 있어야 한다 | Must | 기획 |
| ISS-005 | 이슈의 요약과 타임라인을 볼 수 있어야 한다 | Must | 기획 |
| ART-001 | 이벤트 선택 시 관련도 1위 근거 기사를 즉시 볼 수 있어야 한다 | Must | 기획 |
| ART-002 | 근거 기사의 제목·날짜·본문·원문 URL을 볼 수 있어야 한다 | Must | 기획 |
| ART-003 | 나머지 근거 기사를 관련도 순으로 볼 수 있어야 한다 | Should | 기획 |

## Acceptance Criteria

| ID | 관련 | Given | When | Then |
|---|---|---|---|---|
| AC-005 | ISS-004 | 이슈가 저장돼 있을 때 | 목록을 조회하면 | 토픽·제목·생성시각·이벤트 수가 표시된다 |
| AC-006 | ISS-005 | 이슈가 저장돼 있을 때 | 상세를 조회하면 | 이벤트가 날짜 오름차순으로 표시된다 |
| AC-007 | ART-001 | 이슈 상세가 표시됐을 때 | 이벤트를 선택하면 | 관련도 1위 기사가 추가 조작 없이 표시된다 |
| AC-009 | ART-002 | 본문이 표시 상한을 넘을 때 | 기사를 열면 | 잘림을 알리고 원문 링크를 제공한다 |
| AC-010 | ART-003 | 근거 기사가 2건 이상일 때 | 전체 목록을 열면 | 관련도 순으로 표시된다 |

AC-008의 존재하지 않는 기사 인용 제거는 생성 기능의 저장 전 검증이므로 [`timeline.md`](timeline.md)를 따른다.

## 기능 상세

- 목록: 저장된 이슈를 생성 시각 내림차순으로 조회한다.
- 상세: 이벤트를 날짜 오름차순으로 정렬하고, 이벤트별 근거와 대표 기사를 연결한다.
- 기사: MCP 데이터 접근 계층을 통해 제목·부제목·서비스 일자·본문·원문 URL을 조회한다.
- 기사 본문은 표시 상한까지만 반환한다. 구체적인 상한 값은 구현·화면 검증 후 정한다.

## 대표 기사 선정 정책

1. 근거 1건이면 해당 기사
2. 2건 이상이면 검색 관련도 최고 기사
3. 동점이면 이벤트 날짜에 가장 가까운 서비스 일자
4. 다시 동점이면 기사 ID가 작은 기사

마지막 두 단계는 동일 이슈를 다시 열었을 때 대표 기사가 바뀌지 않게 한다.
