# 타임라인 생성 요구사항

관련 공통 PRD: [`../REQUIREMENTS.md`](../REQUIREMENTS.md)

## 요구사항

| ID | 요구사항 | 우선순위 | 상태 |
|---|---|---|---|
| ISS-001 | 사용자는 토픽을 입력해 타임라인 생성을 요청할 수 있어야 한다 | Must | 기획 |
| ISS-002 | 사용자는 생성이 어느 단계까지 진행됐는지 확인할 수 있어야 한다 | Should | 기획 |
| ISS-003 | 동일 토픽이 이미 있으면 재생성 없이 다시 볼 수 있어야 한다 | Should | 기획 |
| ISS-006 | 토픽이 모호하면 되물음을 받고 의도를 좁혀 진행할 수 있어야 한다 | Should | 기획 |

## Acceptance Criteria

| ID | 관련 | Given | When | Then |
|---|---|---|---|---|
| AC-001 | ISS-001 | 토픽을 입력했을 때 | 관련 기사가 1건 이상 검색되면 | 날짜순 이벤트를 가진 이슈가 생성·저장된다 |
| AC-002 | ISS-001 | 토픽을 입력했을 때 | 관련 기사가 없으면 | 생성을 중단하고 관련 기사 없음을 안내한다 |
| AC-003 | ISS-002 | 생성이 시작됐을 때 | 수집 루프가 진행되면 | 라운드와 현재 단계가 표시된다 |
| AC-004 | ISS-003 | 동일 토픽이 저장돼 있을 때 | 다시 요청하면 | 저장된 이슈를 표시한다 |
| AC-008 | ISS-001 | 존재하지 않는 기사 ID가 생성됐을 때 | 이슈를 저장하면 | 해당 인용을 제외한다 |
| AC-022 | ISS-006 | 모호한 토픽을 입력했을 때 | 의도를 특정할 수 없으면 | 무엇을 알고 싶은지 되묻는다 |
| AC-023 | ISS-006 | 되물음을 받았을 때 | 답하면 | 좁혀진 의도로 생성이 이어진다 |

## 기능 흐름

```text
질의 의도 해석 ⇄ 의도 되묻기
        ↓
가상 타임라인 생성(기간·가상 이벤트)
        ↓
검색 → 핵심 이벤트 선정 → 선후 이벤트 추출 ─┐
 ↑                                           │
 └── 가상 이벤트 생성 ← 충분성 검토 ← 진행 판정 ┘
                              ↓ 충분/종료
                        타임라인 생성
                              ↓
                        인용 검증·저장
```

- 입력: 토픽 문자열과, 필요한 경우 사용자의 의도 보충 답변
- 출력: 진행 단계·라운드 정보, 완료 시 생성된 이슈
- 가상 타임라인과 가상 이벤트는 검색을 이끄는 자료이며 최종 타임라인에 포함하지 않는다.
- 가상 기간은 고정하지 않고 충분성 검토 결과에 따라 바뀔 수 있다.
- 선후 이벤트는 그 시점의 가상 기간 안에서 탐색한다.

## 수집 루프 종료 정책

아래 중 하나를 만족하면 타임라인 생성으로 넘어간다. 구체적인 최대 라운드·깊이 값은 구현 후 정한다.

- 충분성 검토 통과
- 충분성 검토 후 선정 기사 수 변화 없음
- 선후 이벤트 연쇄 깊이 상한 도달
- 최대 라운드 도달

## 내부 예외

| ID | 상황 | 기대 동작 |
|---|---|---|
| EX-01 | 최초 검색 결과 0건 | 즉시 중단하고 루프를 돌지 않는다 |
| EX-02 | 루프 검색 결과와 누적 선정 기사 모두 0건 | 근거 0건인 이슈를 생성·저장하지 않는다 |

LLM·외부 API·저장 실패는 공통 EX-03~05를 따른다.

## 리스크

- 선후 연쇄가 끊기지 않으면 가상 기간과 깊이 상한으로 경계를 둔다.
- 가상 이벤트 유출은 저장 직전 인용 검증으로 다시 차단한다.
- 충분성 판단 체크리스트는 AI 명세에서 정의한다.
